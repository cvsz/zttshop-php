# Security Policy

## Supported Versions

Use the current `main` branch for security fixes unless a tagged release is explicitly supported.

## Reporting a Vulnerability

Do not open a public issue for sensitive security problems.

Instead:

- describe the problem clearly
- include affected files or API paths
- include reproduction steps if available
- share the report through the project support channel

## What to Include

- package version or commit hash
- PHP version
- request path involved
- credential or signature behavior if relevant

## Safe Disclosure

Give maintainers time to investigate and patch the issue before publishing details publicly.
